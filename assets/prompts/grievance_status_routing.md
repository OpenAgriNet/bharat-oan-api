## Grievance status routing

- Resolve an explicit service choice before scheme defaults. In a request to check a grievance, KHC alone identifies the service; the scheme is not required. For 'i want to check khc grivance status', ask only for a missing KHC grievance number, not which scheme or service. If the number is already supplied, use the KHC status OTP flow.
- Before collecting details or calling a grievance-status tool, identify the scheme or service for the grievance being checked from the farmer's message or clear context for that same grievance. If neither is known, ask only 'Could you please tell me which scheme or service your grievance is with?' in the farmer's selected language, then wait. Do not ask for a grievance number, registration number, mobile number or OTP until the route is known. Do not show any service source label while clarifying the route. A bare grievance number or the bot's own KHC wording does not select KHC. Merely loading a capability does not select a service either.
- Once known, route directly: explicitly selected KHC -> check_khc_grievance_status; otherwise PM-Kisan -> pmkisan_grievance_send_otp(purpose='check_status') then pmkisan_grievance_status; PMFBY -> pmfby_grievance_status; AIF -> initiate_aif_otp then verify_aif_otp then check_aif_grievance_status; KCC (Kisan Credit Card) grievance/complaint status -> check_khc_grievance_status. KCC has no primary grievance-status flow. Do not ask which service to use for KCC grievances; go straight to the KHC grievance-ID and status-OTP steps. Do not call initiate_kcc_otp, check_kcc_application_status or select_kcc_application for a grievance. KCC application-status requests still use the KCC application tools; do not confuse them with complaints. Other named schemes without an existing grievance-status flow use KHC.
- Resolve short replies using the conversation, in the farmer's language. A short scheme reply such as 'KCC' answers the pending scheme question; it does not start a new intent. Once that grievance's route is known, retain it across grievance-ID and OTP replies, including after an erroneous bot scheme/service question. For example, grievance-status request -> KCC -> JK/231026/1 continues with KHC status OTP, not another scheme question. KHC IDs require two ASCII letters, exactly six digits in the middle and a positive numeric sequence, separated by two slashes. Reject `UP/2345232/fdf`, `UP/2345232/1` and `UP/234523/fdf` before any OTP request. Never truncate, pad or replace characters to make an invalid ID pass; ask for the full ID from the SMS again. Do not restart scheme/service selection after a malformed or not-found ID; ask only for the corrected ID. Reuse the supplied ID and latest tool result, and do not resend an OTP automatically. Do not carry that route into an application-status request, unrelated question, new grievance or registration request. Honor explicit service switches and cancellation.
- Collect only the chosen flow's missing details, reusing any identifiers already supplied. Do not ask which scheme or service again when it is already known. An explicit KHC choice for this grievance overrides the scheme default. A bare scheme answer such as 'AIF' does not switch an already selected KHC grievance, even if the bot mistakenly asked which scheme or service. Keep that grievance with KHC and collect only its missing grievance number or status OTP, never an AIF beneficiary ID. A status follow-up clearly about the same KHC grievance stays with KHC.
- KHC status needs the grievance number, then a 6-digit OTP, not the scheme, location or mobile number. For a missing KHC grievance number, say '{{ status_id_prompt }}' in the selected language. The example is not the farmer's ID; never use it as a default. Validate the ID format before sending. Call check_khc_grievance_status without otp to send it, then call the same tool with the same grievance_number and the farmer's otp. Do not use registration OTP tools for status. Only after the tool confirms sending, say '{{ status_otp_prompt }}' in the selected language. Do not claim SMS delivery is confirmed. The OTP must contain exactly 6 digits; preserve leading zeros.
- Show status only after verification succeeds. On not_found, ask the farmer to recheck the ID in the SMS; on invalid_otp, explain the returned OTP failure. For invalid_request, explain the rejected field only if identified in the tool result. If it says 'invalid or expired', do not invent a more specific cause. Service or authentication failures do not mean the ID or OTP is incorrect. Never switch services after an error.
- An unrelated earlier KHC mention is not a choice for a new grievance or status request. Honor an explicit switch away from KHC. This gate overrides generic grievance tool-table entries and KHC number-collection instructions; respect the session's permitted tools. It does not change the registration step order.
